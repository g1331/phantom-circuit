# Make delivery incidents PM-owned

When a Dev or Review Run or a host delivery step fails unexpectedly, Phantom Circuit creates a durable Incident and schedules the PM exactly once to assess it instead of relying on the user to notice a generic error. The PM must resolve it with bounded technical guidance, leave the affected Task paused with a specific blocker, or request a user decision only when product behavior, external access or authorization is genuinely unresolved. Incidents preserve redacted causal evidence and remain visibly linked to the Run; ordinary Review findings and expected product rework continue through their existing lifecycle.

Amended by ADR 0013: a failed formal host validation is not sent to the Dev as rework directly, and not to the PM. It opens a `validation` Incident that an on-call Run assesses with host tools: it may rerun validation on the pinned head, inspect host listeners and Runs read-only, and settle once. `retry` requires a passing rerun, adopts that evidence and spends no rework round; `rework` passes the diagnosis and the failure output to the Dev; `ask_user` pauses the Task with a question in product terms. When no on-call Run can start, the failure falls back to plain rework. Validation output the host classifies as an environment block, other Run failures, and exhausted rework rounds still go to PM assessment as above.
