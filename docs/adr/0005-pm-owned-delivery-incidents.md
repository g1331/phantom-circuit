# Make delivery incidents PM-owned

When a Dev or Review Run or a host delivery step fails unexpectedly, Phantom Circuit creates a durable Incident and schedules the PM exactly once to assess it instead of relying on the user to notice a generic error. The PM must resolve it with bounded technical guidance, leave the affected Task paused with a specific blocker, or request a user decision only when product behavior, external access or authorization is genuinely unresolved. Incidents preserve redacted causal evidence and remain visibly linked to the Run; ordinary Review findings and expected product rework continue through their existing lifecycle.

Amended by ADR 0013: a failed formal host validation is not sent to the Dev as rework directly, and not to the PM. It opens a `validation` Incident and resumes the Task's own Dev thread with host tools: the Dev may rerun validation on the pinned head, inspect host listeners and Runs read-only, edit the worktree, and settle once. `retry` requires a passing rerun, adopts that evidence and spends no rework round; `fixed` requires uncommitted edits, spends one round, and the host commits and revalidates them without another implementation turn; `resync` requires the trunk to have moved since the base, and synchronizes without spending a round; `ask_user` pauses the Task with a question in product terms. Rerun, `retry`, `resync` and `ask_user` are refused while the worktree has uncommitted edits. When no such Run can start, the failure falls back to plain rework. A separate on-call role briefly did this diagnosis; it diagnosed code it had not written and handed its reading to a Dev who then started cold, so the role was folded into the Dev. Its historical Runs keep the `oncall` role and recover as the Dev. Validation output the host classifies as an environment block, other Run failures, and exhausted rework rounds still go to PM assessment as above.

If validation diagnosis throws or finishes without a valid disposition, the same Incident transfers to the existing PM assessment queue with the original failure and the next diagnostic step. The PM Run and its assessment claim are saved together; startup also reconciles a diagnostic failure recorded just before that handoff. This preserves the Task, worktree, partial edits and pinned validation evidence instead of treating a technical interruption as a user question. Explicit user pauses, cancellation and recorded user questions remain authoritative; normal retry, fix, trunk resync and user-question dispositions retain their existing gates.
