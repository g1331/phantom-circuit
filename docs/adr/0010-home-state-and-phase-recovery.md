# Keep execution state independent of the source checkout

Authoritative state lives under the user's home `.phantom`, with a consistent SQLite snapshot, independently verified rollback copy and drift checks protecting adoption of old checkout-local data. Registered worktrees that cannot be safely relocated retain explicit task-to-root mappings while new worktrees use the home root; process-lifetime ownership prevents competing hosts, including after a crash. Startup reconciles interrupted phases before new claims, applies the Project's automatic or manual recovery policy, and associates at most one successor with each recovery without replaying uncertain external writes or resuming user-paused work.

Review Clarifications persist their asking Run and at most one successor Review Run. Accepting a question also completes its asking Run in the same transaction, so restart cannot replay it as an interrupted review. Answer completion is reconciled from durable state and releases only its own wait; independent user pauses and terminal Task states remain authoritative. Revision drift or dirty worktrees preserve answers and evidence and enter the existing blocking/Incident coordination path without a Dev claim, retry charge, implicit default-branch merge or automatic validation. A default branch advancing alone does not alter the pinned review. An interrupted successor continues through normal phase recovery.
