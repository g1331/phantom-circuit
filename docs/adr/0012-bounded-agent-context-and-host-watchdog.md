# Bound agent context and watch Run progress from the host

A PM turn previously carried every Task, message and design record of its Project; on a real Project this reached about 890,000 characters per turn, and each Dev turn inlined five full skill bodies, one of which told it to commit despite host-owned finalization. The PM now receives a bounded summary — unfinished Tasks, recent finished Tasks, the latest messages and document identities, with long fields clipped — and recalls full records by id through the read-only `read_project_records` tool, scoped to its own Project. Skills are an optional method library: each role sees a catalog of pinned skill names, purposes and paths and reads a body only when its Task calls for it; the merge-conflict method is inlined only for a live conflict, and host rules override any skill step about commits, pull requests, reviews or subagents.

Because many agent failures are silent rather than crashes, the host watches every live Run: a Run with no backend event for twenty minutes, or one repeating the same command five times without an edit, is stopped as a failure and enters the existing Incident assessment instead of being treated as a user pause. A Dev blocked on `ask_pm` is served ahead of queued PM work, while user messages, recovery and Incident turns keep their FIFO order and their one-source authority; batching several PM triggers into one turn was rejected because each PM Run answers one triggering source (and at most one Task context). This binds the trigger, not the output: one user message may still create several Tasks. A settled completed Task leaves GitHub polling, and Project status is written only when it changes.
