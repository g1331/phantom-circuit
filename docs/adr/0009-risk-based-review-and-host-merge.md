# Review once and escalate only when risk requires it

A Task normally receives one fresh-context combined review; complex Tasks, rework and an explicit primary escalation require a second review with a different actual model from the current implementation and primary review. Current-revision tests, the required review verdicts and remote head/base/check evidence authorize the host to merge without a further PM acceptance model call; completed legacy Tasks retain their original evidence policy. Each independently deliverable requirement normally becomes one Task together with its necessary domain documentation (one message may carry several requirements and so create several Tasks), replacing separate document-publication and dual-axis review lifecycles.

`needs_user` suspends the asking review without code rework or retry consumption. Once all questions are answered, the host verifies the pinned local worktree (including uncommitted changes) and PR identity/head/base, then claims one fresh Run for the same review role on the same version. The asking verdict remains history and is superseded only by that new Run; same-version tests and other completed reviews remain valid. User answers are included with the questions and their original version in subsequent review input, including as context after later changes. A new version still follows normal validation and review invalidation, and only the required valid verdicts authorize merge. Code, test or documentation defects still use `rework`; ordinary host verification does not become a user question because a Dev sandbox cannot perform it.

The Clarification binds the original PR, repository and head/base branch names. Its recovery accepts an advanced tip of that same base branch only after Git proves the fixed base is its ancestor, fetching missing objects through the host workspace boundary when necessary. Review still uses the original head/base; retargeting, rewritten history and failed verification block for coordination. This recovery exception does not change finalization's existing current-base checks or authorize a merge on a different version.
