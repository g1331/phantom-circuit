# Verify a legacy merge from host records, not from the source tip alone

An unfinished merge found in a task worktree is normally proven by the tracked source ref still pointing at exactly `MERGE_HEAD`, but a default branch that advances after the merge started makes that test permanently false, so the host would refuse a still-valid merge forever. The host therefore also accepts an advanced source, but only when three independent records agree: the target baseline the host itself recorded for the task (`targetBase`, or the legacy `base` that stored the default-branch tip the merge was started from), a durable host merge-coordination event that must name this exact `HEAD`/`MERGE_HEAD` pair once its wording names commits at all, and repository history showing `MERGE_HEAD` reachable from exactly one allowed source that advanced from it, still outside the task HEAD, on the recorded integrated baseline. `MERGE_HEAD` merely existing, merely equalling `task.base`, or merely being an ancestor of the current default branch is not sufficient on its own, and a missing record, conflicting records, a rewritten branch, an ambiguous second source, revision drift or an unknown Git result pauses the task with the specific reason instead of merging. Two allowed refs that advanced to the same commit are the same pending merge and cannot change its outcome; refs that advanced to different commits are ambiguous and refused.
